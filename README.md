# Homeworld 1 Classic Fix

Source for the **HW1ClassicFix** installer published on Nexus Mods: fixes for *Homeworld 1
Classic* as shipped in the Homeworld Remastered Collection (Steam and GOG), 2023 game build
(`Homeworld1Classic\exe\Homeworld.exe`, 3,591,168 bytes, SHA-256
`421c114e832c56bd1994fe97c342969ef69881bb74399e67bef979c6923df381`).

No game files are in this repository or in the download. The installer rewrites a fixed set of
bytes inside the player's own copy of `Homeworld.exe`, in place, after verifying every byte it is
about to change, and keeps a backup.

## What the fix does

- **Docking.** The July 2023 rebuild of the executable compiled every floating-point `ABS()` in
  the ship-avoidance code as an integer truncation, so obstacle sizes along a direction came out
  as zero. Fighters and corvettes ordered to dock with the Kushan Mothership never received the
  "destination obscured" signal and circled it forever. The patch restores the float absolute
  value at every affected site (56 small instruction rewrites, same size, no code added).
- **Resolution list.** The Video options only offered five 4:3 and 5:4 modes because of a
  hard-coded whitelist and a 1600-pixel width cap. Both are removed, and the mode list is built
  in sorted order (colour depth, then height, then width).
- **Move order at widescreen ratios.** The cursor-to-world ray assumed a 4:3 frustum; it now
  scales with the real window aspect, and the projection aspect is recomputed when the
  resolution is changed in-game.
- **Settings on Windows 10/11.** The game opened its settings key under `HKEY_LOCAL_MACHINE`
  with full access, which standard users do not have, so it fell back to 640x480 unless a
  compatibility mode switched UAC virtualisation on. The key is now under
  `HKEY_CURRENT_USER\SOFTWARE\Sierra On-Line\Homeworld`; the installer copies old values there.
- **First run** starts at the desktop size instead of 640x480; default colour depth is 32-bit.

Every change is a same-size, in-place byte patch (74 sites). The full table with the original
and replacement bytes and a note per site is `installer/PatchTable.cs`, generated from
`scripts/dockfix_patch.py`, which also documents the reasoning per site.

## Repository layout

| Path | Purpose |
|---|---|
| `installer/Program.cs` | The installer: WinForms window, auto-detection (Steam, GOG), per-site verify, install, remove, settings copy; also a console mode (`--check`, `--install`, `--remove`, `--detect`). |
| `installer/PatchTable.cs` | Generated byte table (do not edit by hand). |
| `installer/app.manifest` | `asInvoker`, DPI-aware. |
| `installer/README.txt` | The text shipped inside the download. |
| `scripts/dockfix_patch.py` | Reference implementation of the patch (Python 3, standard library only): `check`, `apply`, `revert`. |
| `scripts/gen_patchtable.py` | Emits `installer/PatchTable.cs` from `dockfix_patch.py`. |
| `scripts/reloc_check.py` | Simulates the Windows loader's base relocation to prove the rewritten code survives ASLR. |
| `scripts/build_installer.ps1` | Build, self-test and packaging script. |

## Building

Requirements: Windows 10 or 11. Nothing else: the installer is compiled with the C# compiler that
is part of the .NET Framework 4.x already present in Windows
(`%WINDIR%\Microsoft.NET\Framework\v4.0.30319\csc.exe`). Python 3 is optional (it regenerates the
patch table; without it the committed `PatchTable.cs` is used).

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_installer.ps1 -SkipTests
```

Output: `build\HW1ClassicFix-Setup.exe` (about 39 KB). Compiler command, for reference:

```
csc.exe /target:winexe /platform:anycpu /optimize+ /win32manifest:installer\app.manifest
        /r:System.dll /r:System.Core.dll /r:System.Windows.Forms.dll /r:System.Drawing.dll
        /out:build\HW1ClassicFix-Setup.exe installer\Program.cs installer\PatchTable.cs
```

The .NET Framework compiler does not produce byte-identical binaries across builds (it embeds a
fresh module ID and timestamp), so a rebuilt exe will not hash the same as the published one; its
behaviour is identical.

### Self-test

With an unmodified 2023 `Homeworld.exe` at hand, the script installs into a throwaway copy of the
game folder layout (via a subfolder, to exercise folder resolution), checks that a second run is a
no-op, compares the result with the Python patcher, removes the patch and checks the file is
byte-for-byte the original again, and confirms a folder without the game is rejected:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_installer.ps1 -OriginalExe "D:\path\to\unmodified\Homeworld.exe"
```

Expected SHA-256 of a fully patched exe: `166c3a23a0eeb5789823602b2571be98ae926a9447376c4b843ac0d1179884fb`.

## What the installer touches on a user's machine

- Reads: the Steam registry keys and `libraryfolders.vdf`, the `GOG.com\Games` registry keys and
  a few common folders, to find `Homeworld1Classic\exe\Homeworld.exe`.
- Writes: that one file (after saving `Homeworld.exe.orig-2.303` next to it), and the user's own
  `HKEY_CURRENT_USER\SOFTWARE\Sierra On-Line\Homeworld` key (copy of the old settings).
- No network access, no services, no files elsewhere. It refuses any executable that is not the
  supported build or that another patch has already modified at the same places.
